# 独立缺陷检查后的修复（2026-10-15）

对应 `BUG_AUDIT_CURRENT_2026-10-15.md` 中实际复现的4项问题。

## 修复行为

1. 班级正在保存或删除时，应用内切换课程标签和退出登录会被阻止，并提示等待。保存完成或失败后解除限制。离开浏览器页面仍使用浏览器的未保存提示，不能承诺撤销已经发给服务器的写请求。
2. 自动班名保存后仍可跟随第一位学生的档位调整；明确手动输入的名称保持原样。手动输入的文字即使恰好与自动建议相同，也按手动名称保留。可点击“恢复自动命名”重新跟随档位。
3. 班级、冲突提醒和广播独立更新。提醒或广播失败不会隐藏正常班级，失败项目有明确提示和重试入口；已有提醒失去更新时不会被描述为“没有冲突”。
4. 首次探测身份时，正常的未登录401安静显示登录页面；已登录期间发生会话失效，仍清空敏感状态并提示重新登录。

## 数据库升级

schema从v3升到v4，为班级增加`name_is_manual`。旧库在显式事务迁移前通过SQLite Backup API备份到数据目录`backups/migration-v3-*.sqlite3`，事务中重新检查版本并检查外键。新建库直接具备该字段。

旧记录没有保存自动/手动来源，升级时保留原名，按手动名称处理，不猜测覆盖老师输入。**已有班级如需名称跟随档位，在编辑时点击“恢复自动命名”并保存一次。**历史快照不改写，账号和学生档案保留。恢复工具继续兼容v1/v2/v3备份，启动时依次迁移；v1重建时只复制旧表实际存在的列，新增命名字段使用保守默认值。

升级主机请先停止旧服务并另行备份，再使用新版启动服务，保持原数据目录配置。

## 本机环境修复

原`.venv`配置指向失效解释器，已备份`pyvenv.cfg.before-repair`并更新为本机可用Python 3.12.14。原依赖保留，并从随包离线依赖核验；`pip check`无损坏依赖，关键模块导入通过。使用修复后的原`.venv\Scripts\python.exe run.py start`成功运行隔离测试服务。

`首次运行.bat`现在会检测已有虚拟环境的解释器版本、位数和可执行性；已安装Python Launcher的主机可用Python 3.12升级修复失效环境。未安装Launcher的本机没有执行完整交互式setup流程，不把此流程计作通过。
