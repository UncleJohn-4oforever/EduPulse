# 主动冻结与贡献因素对比

主管侧新增「数据冻结与对比」。点击「冻结当前数据」填写名称、备注，保存全校区当时已保存的完整报表数据和三个指标值。操作独立于广播，后续教师编辑不影响旧记录。无修改或删除冻结记录的接口。教师不能访问冻结、列表、详情及对比API。

选择旧记录B、新记录A后，分别展示一对三满班率、一对六满班率、科目比的前后值、差值和计算依据。变化按以下方式归类：

- 满班率：按稳定班级编号匹配，解释新增/移除班级、人数增减、班型调整。列出教师、班名、编号；展开可看席位/容量、学生关联和档位。
- 科目比：按稳定学生编号匹配，解释新增档案、移除档案、科目数调整。科目按每名学生去重，分母包含全校区全部当前档案（包括未关联班级的学生）。
- 学生合并：冻结时记录审计中的合并映射，对比时追溯合并链，保留旧记录各原始档案的科目数和学生数。合并统一标注为档案合并，不误报为学生流失。
- 改名、评价变化、不影响计数的学生调班等不列入指标因素。只显示冻结点之间的净变化，不重放中途撤销的操作。

方向以旧指标R为基准：单条变化的分子变化ΔN减去R乘以分母变化ΔD，大于零归为拉高，小于零归为拉低，等于零归为其他相关变化。这个规则同时呈现抵消因素，所有变化的分子/分母增量可与两个冻结点的差额核对。第一版不显示单条变化贡献的百分点，不推测开班或退课的业务原因。旧或新分母为零时显示「—」，不判断方向。

技术与兼容：新增frozen_records表，schema升级至5；兼容v1–v4旧备份恢复。冻结在SQLite写事务中读取，保证教师/班级/学生/合并映射属于同一版本。历史广播功能保持原有行为，主动冻结记录单独保存。

验证：74项后端测试通过；浏览器验收覆盖主动命名冻结、继续编辑、历史不变、新增一人班与科目比解释、查看详情、先后记录约束、刷新持久化、教师端无入口，以及1440/1280/1024/768/390/360六种宽度。截图使用虚构数据，位于docs/screenshots/freezes/。
