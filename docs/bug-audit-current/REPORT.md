## 已复现问题

### 1. [P2] 校区筛选漏掉尚未关联班级的学生，抬高科目比

位置：backend/app/reports.py:83。

同一校区创建两名学生，其中一名有一个数学班，另一名尚未关联班级。全部校区显示2名学生、1个学生科目，科目比0.50；选择唯一校区后只剩1名学生，科目比变成1.00。两名学生的campus_id相同，实际没有改变统计地域。原因是校区过滤依赖班级详情ds，空详情被直接排除，未使用未关联学生的档案校区。

影响：科目比分母、学生档案数量、学生列表和相应导出的范围。只选校区时应保留该校区尚未关联班级的档案；科目或教师筛选应继续按相应关联筛选，不能直接删除全部ds过滤条件。

证据：reproductions.json的id=1，复现脚本内真实API断言。

### 2. [P2] 新筛选读取失败时，旧结果被显示在新条件下

位置：frontend/src/main.tsx:48。

先显示有数学班的数据，再选择英语，并模拟新报表请求返回503。页面只弹出错误提示，仍保留原数学教师行和科目比；筛选框已经显示英语。对同一英语条件直接请求服务，正确结果为0名教师，界面却仍显示1名教师。

影响：在服务暂时不可用时可能误读旧统计，且页面与按新条件发出的导出不一致。建议让报表数据与其请求参数绑定；失败时明确展示读取失败及重试，不能把旧数据作为新条件的结果，并在当前条件未成功加载时停用导出。

证据：failed-filter.png，reproductions.json的id=2。

### 3. [P2] 慢对比请求会覆盖新记录选择后的结果

位置：frontend/src/FreezeWorkspace.tsx:18–21。

开始B→A对比并延迟其响应，随后点击「冻结当前数据」创建C。界面自动把选择框改为A→C；此时释放原B→A请求，旧响应仍执行setComparison，结果区变成B→A，与选择框不一致。

影响：网络较慢、同时冻结时可能对照错误的记录。建议对比请求绑定当时记录ID和请求序号；选择记录或新建冻结后作废旧请求，只有仍对应当前选择的响应可以更新结果。

证据：stale-freeze-comparison.png，reproductions.json的id=3。
