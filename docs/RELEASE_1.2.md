# EduPulse 1.2 — 删除管理与学生档位

2026-10-14。本版按新增需求实现三项改动。使用技术栈及Windows离线运行方式保持不变，没有上传GitHub。

## 1. 主管删除教师、年级、科目和校区

教师账号页新增「删除」。确认框会提示当前班级数量，并明确说明：删除教师的当前班级、学生报名关联、档位与评价，立即撤销其登录；保留学生基本档案、其他教师的关联、已冻结历史快照和审计。教师身份以删除标记留在数据库，供旧广播和审计追溯，不显示于当前名单、统计或新广播选人，不能通过启用或重置密码重新打开已删除教师。该删除不能在页面直接撤销，操作前应备份。

设置页的每个类别旁新增X按钮，支持删除校区、科目、年级。删除从新记录的可选项移除，已有引用和名称仍保留；旧班级可以继续沿用原类别并维护学生评价/安排。新的班级/学生/教师不能使用已删除类别。输入同类型、同名称重新添加，会恢复原类别ID。原校区被删除时，请把教师转入有效校区再创建新班级/学生。

所有删除需主管权限、CSRF验证和明确确认，写入审计。教师不能调用删除教师/类别接口。广播的固定目标人数不因删除教师改变，进度名单会标注已删除。

## 2. 每天六档，时间选填

每条学生时段均选择星期一至星期日，以及第1至第6档。不再让老师自由输入档位名称。开始/结束时间都可以留空；若填写则同时填写，结束晚于开始。六档本身不预设具体时间，主管不需要先配置时钟表。

新加入学生默认显示周三第3档，老师可以立即调整，并为同一学生添加多条周档位。一位学生至少一条，最多42条（7天×6档），不能重复同星期同档。

## 3. 档位归属于学生

每张学生卡片包含：姓名/编号、该生的周档位、A/B/C、文字评价。班级基础字段中删除了独立的时段编辑区；所有安排随整班保存一起提交，刷新后预填。

时段挂在enrollment（学生在具体班级/科目的关联），不会在全局student上放一套共享时间。同一学生在数学和英语可以分别安排。

用户确认的教师负荷口径为：**同班、同星期、同档位合计1节**。不同学生的共同档位在班内去重，不乘学生人数；不同班分别计数。例：甲周三第2档，乙周三第2档和周四第6档，全班每周2节。删除乙后剩下1节；没有学生的空班为0节。没有增加自动排课或跨班时间冲突检查。

同班共同档位的具体时间若填写须一致；一个学生留空、另一个填写可以保存，班级汇总显示已填写时间。学生自己的明细仍按其实际填写保留。

学生明细及XLSX新增上课档位字段，班级/负荷统计使用同一后端并集。PNG/XLSX标明新口径。旧快照依然读原JSON，保留原轮次数据及原统计口径。

## 从现有电脑升级

1. 用旧程序运行backup.bat，妥善另存备份，然后停止start.bat窗口中的服务（Ctrl+C）。
2. 将新版解压到新的程序目录。不要删除或覆盖 `%USERPROFILE%\EduPulseData`，它是默认业务数据目录。
3. 原来有自定义`.env`的，将它复制到新版程序目录，保持同一个EDUPULSE_DATA_DIR、同一个Windows用户。
4. 运行setup.bat安装依赖和升级数据库；已有管理员会提示账号已存在，不会重置。然后运行start.bat。
5. 浏览器刷新页面（必要时Ctrl+F5），继续使用原账号。无需重新建立教师、班级或学生。

数据库升级为schema v3，启动或init-db时自动执行：v1先做稳定ID迁移到v2，再迁移v3。迁移前用SQLite Backup API保存旧库到数据目录backups；v3添加教师/类别删除字段，并把原班级的每条时段复制到班内每条学生报名关联，保留原评价和历史JSON。事务提交前检查外键，重复执行不重复复制。

旧“一档/三档/第6档”等明确名称可以映射为六档；任意旧文字名称不会被猜测，保留原文、星期和具体时间。页面提示老师人工选择第1至第6档后再保存。旧版若存在重复同档/冲突时间，也需要老师核对整理。新统计按新口径计算，旧历史快照不重算。

恢复工具继续支持v1/v2备份的表结构，恢复后再次启动会自动升级，并清空旧会话。若升级失败，停止服务并保留报错、自动备份，不要删除原数据目录。
