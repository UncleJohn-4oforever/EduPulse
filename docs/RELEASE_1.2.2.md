# EduPulse 1.2.2：实时广播修复与排课撞档提示

## 修改范围

实时统计只关联已开始、未截止且尚未结束的广播；有多个有效广播时继续使用最近创建的一轮。手动结束、全部目标教师确认或超时后的广播不会继续把旧确认状态附到当前数据上。指定历史广播时仍读取原始快照。

教师的「我的班级」新增可展开的排课撞档提醒。主管在「教师负荷」实时列表的各教师栏中看到提醒及涉及的班级、星期、档位和时间。

- 同一教师、不同班级、同一天且双方具体时间完整：只在时间区间重叠时提示「时间重叠」，档位编号不同也会检查；首尾相接不算重叠。
- 任一方具体时间不完整，且星期、已确定的档位编号相同：提示「可能撞档，待核对」。
- 双方时间完整且不重叠，即使档位编号相同，也不提示撞档。不同教师的班级不相互比较。
- 按班内档位并集检查，多个学生共同上课不会重复提示。一处提醒是一对班级的一对重叠或待核对时段。
- 提醒针对已保存的排课，保存后和收到数据更新时刷新。允许继续保存，既有班内时间一致性校验保持原样；不同班的课次仍分别计数。

检查通过独立的只读接口提供：`GET /api/teacher/schedule-warnings`（仅本人），`GET /api/admin/schedule-warnings`（主管）。不把提醒加入统计或历史快照JSON；历史页面不显示当前排课提醒。

## 筛选口径保持原样

`backend/app/reports.py` 未修改。按用户确认保留现有行为：

| 条件 | 既有作用范围 |
| --- | --- |
| 年级 | 按学生档案年级筛选学生；不按班级年级裁剪教师统计或班级 |
| 学生姓名 / 编号搜索 | 搜索学生档案；不裁剪教师统计和完整班级席位 |
| 教师选择 | 限制教师统计、班级及学生的授课明细；没有相应授课关联的学生不保留 |
| 教师姓名 / 账号搜索 | 筛选教师及其班级，并限制学生授课明细 |
| 科目 | 限制教师班级及学生科目明细，并据剩余完整班级重算教师统计 |
| 校区 | 按教师所属校区及学生授课明细所属校区筛选，沿用原实现 |

学生科目数按筛选后剩余明细计算。学生姓名或年级筛选不会把班级席位改成搜索结果人数；以这些条件导出XLSX时，学生工作表被筛选，教师和班级工作表仍按其原有范围统计。

## 本轮验证

先编写测试并在1.2.1上执行：11个复现用例失败，1个既有筛选口径测试通过；随后实施修复。最终后端自动测试 **52项全部通过**（原有40项及新增12项）。测试覆盖结束广播的三种路径、有效广播回退、未来/超时广播、实时XLSX确认清单、历史JSON内容不变、撞档分类、相邻时间、教师隔离、只读操作、非阻断保存和未改变的统计口径。

5组Chromium浏览器脚本全部通过，包括新脚本 `scripts/browser-schedule-review.cjs` 及原有四组完整流程/回归脚本。新脚本验证教师与主管展示、UI保存、提醒清除、实时/历史隔离和390px移动端布局。TypeScript检查及生产构建通过。

测试使用独立临时SQLite数据库和虚构记录，没有删除或重置业务数据库。`db.py`、`schemas.py`、迁移和快照存储格式均未改变；schema仍为v3。测试环境为Linux云端与Chromium，未在实体Windows电脑安装验收。pytest存在一条测试依赖的弃用警告，不影响通过结果。
